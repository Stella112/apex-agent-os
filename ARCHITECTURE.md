# APEX authority boundaries

APEX means Adversarial Portfolio Engine. It is a decision desk under development.

Public Binance REST -> deterministic Quant -> Ollama Bull / external Bear -> evidence validation -> debate/router -> versioned Constitution Referee -> APEX Guardian execution firewall -> persisted decision -> UI.

Live analysis requires configured providers; no deterministic analyst replaces an unavailable live model. CLI fixtures remain explicitly simulated. The HTTP fixture routes are retired and HTTP replay requests are rejected.

Quant and Referee are JavaScript, despite the earlier Python specification. Preserve the functioning implementation while tracking the discrepancy. The portfolio engine models simplified derivatives P&L; it must not be represented as a spot account or complete live margin engine. Existing spot and futures market inputs remain mixed and require further market-specific reconciliation.

The external Bear accepts a configured HTTPS chat-completions endpoint. Evidence-key validation checks citations exist; it does not prove prose is true or model confidence calibrated. Narrative content is untrusted evidence and has no executable authority. APEX Guardian is a deterministic post-Referee execution firewall: it cannot approve a rejected proposal or weaken Constitution policy, and it fails closed when terms, evidence freshness, account binding, duplicate-order state, or verified write capability are missing.

ExecutionCoordinator is an isolated internal implementation tested with a mock provider. It reserves one account at a time, binds identity/session/preview, persists intent, retains ambiguous outcomes and queries after restart. It is not connected to the HTTP order path. Real account/schema normalization, quantity/fill completeness and session authentication are unfinished. Binance adapter writes and HTTP confirmation remain blocked even if an environment variable requests live execution.

Purchase policy is preflight only. It has no wallet, signature or settlement capability. Integer base units are compared for configured budgets. Caller-provided verification flags are not a substitute for a trusted provider adapter.

DecisionStore atomically replaces a checksummed JSON record in a private directory. One process must own that directory. Journals bind sequence, environment and payload. An owner can rewrite an entire chain; truncation needs a separately trusted head/length. No claim of immutability or source truth is made. The revised journal hashing format is incompatible with legacy records lacking the same hashed fields.
