01 / GETTING STARTED

From a market idea to a reasoned decision.

APEX finds market conditions worth investigating, asks two analysts to challenge the evidence, and checks a proposed position against portfolio rules.

The dashboard works without a Binance login. Use Markets for discovery and Agent review for your own proposal. To use APEX alongside your Binance account, add APEX and the official Binance MCP server to the same compatible AI client.

APEX produces analysis. Your AI client coordinates the two servers; Binance handles account authorization and user-confirmed execution. Installing both servers does not automatically make APEX a mandatory gate for every Binance action.
  1. Open Markets and inspect a route. Read its condition, indicator and caveat.
  2. For a BTC/ETH directional proposal, choose Review and enter your actual book, quantity and invalidation price.
  3. Read the Bull, Bear, Referee and Guardian results. Open Decision record to inspect source fields or download the review.
  4. For execution, continue in your own AI client using its separately authorized Binance connection.
02 / DISCOVERY

Understand the scanner.

The default scan ranks Binance spot USDT pairs by 24-hour quote volume and inspects the top 12, excluding several stablecoin pairs. Detailed analysis also needs a corresponding perpetual market. Failed reads are counted and excluded. This is a liquid sample, not a complete scan of every Binance product.

RouteWhat it measuresHow to read it
Funding carryLong spot / short perpetual funding, indicative fees, spread and flow.CANDIDATE means the screening conditions pass. It does not mean both legs can be executed safely.
Trend watch24-hour versus 168-hour averages, extension, volatility and trade imbalance.WATCH is a research condition; NO TRADE indicates extension or one-sided flow.
News sentimentRecent matched RSS headlines, deduplication and a text-based sentiment label.A headline sample, not measured social consensus. No matched headlines means no coverage.

Scores are heuristic rankings from 0–100, not win probabilities. Annualized carry assumes the observed rate persists; actual funding, fees, basis and leg execution can change. Inspect the route's caveat before interpreting the estimate.

Use the symbol filter and route dropdown to narrow the current scan. Refresh requests fresh market data. Inspecting a symbol also refreshes its news.

03 / ANALYSIS

Four distinct responsibilities.

Bull · AI analyst

Makes the strongest supported case for exposure and cites evidence keys.

Bear · AI analyst

Challenges exposure using the same packet. Agreement is possible; disagreement is not manufactured.

Referee · code

Checks the resulting portfolio, including leverage, concentration, invalidation risk, liquidation distance and session loss.

Guardian · code

Checks freshness, policy and execution authority. It cannot grant account access or override a failed rule.

Enter wallet balance in USDT; quantity is in the base asset. A negative existing quantity means short. Supply the entry price for an existing position, and your actual session opening equity for the loss check. Invalidation is the price where your thesis stops being valid.

The browser form evaluates a single BTCUSDT or ETHUSDT directional position in the USDⓈ-M cross-margin model. A carry route has two legs and is not fully modeled by this form. Values you enter remain user-supplied even if copied from Binance.

Reading a result

  • APPROVE: the proposal passed the modeled rules. It is not an order, a guarantee or an execution authorization.
  • DENY: at least one rule failed. The observed values and rule details explain why.
  • MODEL_UNAVAILABLE / AGENT_INVALID: analysis is incomplete. No substitute argument is generated.
  • Guardian BLOCK: inspect the checks. Missing execution authority is expected on the public decision service.

Decision record exposes the source classification, freshness, formulas and journal hashes. Download the JSON to retain your result; reloading clears the browser's current review.

04 / MCP SETUP

Give your agent two connections.

Use an AI client that supports remote MCP over Streamable HTTP. Client support for plain HTTP, authentication and configuration formats varies. APEX has no OAuth login; Binance has its own authorization flow.

1. Add APEX

Open your client's MCP/server settings, choose a remote HTTP server, name it apex, and enter this URL:

http://38.49.209.149:4174/mcp

For clients that accept a mcpServers configuration, the following is an example. Confirm your client's format before using it.

{"mcpServers":{"apex":{"url":"http://38.49.209.149:4174/mcp"}}}

The temporary endpoint uses HTTP. Some hosted clients require HTTPS and will reject it. Once the domain is configured with HTTPS, replace the URL with that endpoint; the server path remains /mcp. A browser visit is not an MCP connection test.

2. Add Binance separately

Follow the client-specific tab in the official Binance setup guide. Its endpoint is https://agent.binance.com/mcp/agentic. Complete Binance authorization in your client and select the scopes you need. Account and product eligibility apply. Binance requires confirmation for trades and transfers; withdrawal scope is unavailable.

Do not enter Binance API keys into APEX. Your Binance login stays with your client's Binance MCP connection. The APEX server does not inherit it.

3. Verify both connections

Call apex_status and list APEX's available tools.
Then use Binance MCP to read my Agentic account balance.
Tell me which server handled each request. Do not place an order.

Expect four APEX tools below. A successful tools list proves discovery, not live model readiness. Run a review to verify inference.

05 / TOOL REFERENCE

Four read-only tools.

ToolArgumentsResult
apex_status{}Build, provider configuration and decision-service boundary.
apex_find_opportunitiesOptional symbols: 1–12 Binance symbol strings.Ranked routes and unavailable reads. Omit symbols for the liquid USDT sample.

Review arguments

{
  "book": {
    "walletBalance": 1000,
    "positions": []
  },
  "sessionOpeningEquity": 1000,
  "proposal": {"symbol": "BTCUSDT", "side": "LONG", "qty": 0.001},
  "thesis": {"invalidation": 70000}
}

These are syntax examples, not suggested trading values. Use current, accurate inputs. A held position has symbol, signed qty, and positive entryPrice. The portfolio accepts BTC/ETH positions; duplicate symbols must be combined. Proposal side is LONG or SHORT, quantity must be positive. The proposal entry defaults to the freshly fetched mark.

binance_market_data is a reserved field and is currently ignored. APEX fetches its own public market evidence. The book is always caller-supplied; APEX does not verify account ownership. A missing session opening value cannot establish your actual session loss.

Developer check with curl

For testing transport and discovery only; users normally configure the URL in their client.

curl -X POST http://38.49.209.149:4174/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

MCP requests are JSON-RPC POSTs. Initialize first in a real client. The server is stateless and does not provide a long-lived SSE stream. It returns tool failures using isError; inspect the content rather than assuming HTTP 200 means analysis succeeded.

06 / YOUR AGENT WORKFLOW

Ask for an evidence-backed review.

Use Binance MCP to read my current positions and balances.
Use APEX to scan opportunities. Explain the candidates and uncertainty.
For a supported BTC/ETH proposal, map my full relevant book into
apex_review_trade and use my actual session opening equity.
Show the Bull, Bear, Referee and Guardian results.
Do not execute from a stale review or assume an APEX verdict grants authority.
If I later ask to trade, re-check the exact order and account in Binance,
ask me to confirm, then verify the order status through Binance MCP.

APEX's authority check will remain blocked because it does not own your Binance connection. Your client must explain that boundary, not claim APEX authorized an order. An enforced cross-server execution gate is not implemented in this release.

07 / COVERAGE

Know what is modeled.

  • Discovery: liquid USDT spot/perpetual evidence, up to 12 symbols per request. Explicit symbols can be requested through MCP. Missing counterpart markets are unavailable.
  • Portfolio review: BTC and ETH linear USDⓈ-M cross-margin estimates. Static maintenance tiers are assumptions, not your account's live leverage brackets.
  • Not modeled: spot portfolio risk, isolated margin, inverse contracts, options, Earn products, stock instruments, a full two-leg carry portfolio or account-specific execution costs.
  • News: public RSS coverage. No X/social firehose. Missing coverage is not neutral sentiment.
  • Privacy: no owner account data or keys are provided to visitors. Submitted book and evidence are processed on the APEX server and by the configured model providers; review records may be stored on the server.
  • Execution: APEX's public dashboard and MCP submit no Binance orders. Binance execution remains in the user's own client.

“Service online” means the API responded. It does not prove both models can generate a valid answer. A completed live review is the stronger check.

08 / HELP

When something stops.

Market scan times out or returns unavailable symbols

Retry Refresh. Binance reads can fail or a spot symbol may not have the required perpetual. Check the unavailable count and use explicit supported symbols in MCP. Do not treat the last visible result as a new quote.

The agent is unavailable or the debate fails

Retry after the active review finishes. The service uses a local Bull model and an external Bear. Provider access, latency or invalid JSON may stop either one. No Referee verdict is issued when the debate is incomplete. The operator must inspect provider diagnostics if it persists.

My MCP client rejects the URL

Verify remote Streamable HTTP support and the exact /mcp path. Hosted clients may require HTTPS. The temporary HTTP IP cannot satisfy that requirement; use the HTTPS domain when available. Client-specific configuration is not universal.

Binance login works but APEX doesn't show my balance

This is expected. Your client owns the Binance session. Ask it to read your account through Binance MCP and supply the supported book to APEX. The public website does not sync personal balances.

The Referee approves but Guardian blocks

A portfolio check is distinct from execution authority. APEX's shared service has no account-bound order permission. Read each Guardian check; do not bypass failed risk checks or describe this result as an authorized order.

Why can't I review SOL, a spot trade or a carry pair?

The scanner covers more instruments than the current liquidation model. BTC/ETH directional cross-margin reviews are the supported scope. Broader product models require their own validated inputs and risk calculations.
