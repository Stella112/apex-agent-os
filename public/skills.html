01 / WHAT IT IS

Teach any compatible agent to use APEX before Binance.

The APEX Binance Council Skill is the reusable instruction layer for Codex, Claude, Cursor, ChatGPT, Antigravity, and other clients that support agent skills or MCP tools.

APEX is the reasoning layer.
Binance Skills and Binance MCP remain the source of truth for authorization, balances, positions, and trading. APEX never needs your Binance API key.
Users speak normally.
They can say “find promising perpetuals,” “what is moving SOL?”, or “review this trade.” The agent selects the APEX tools, runs Bull, Bear, Referee, and Guardian when appropriate, and explains the result without asking users to write JSON.
02 / REQUIRED WORKFLOW

Scan → debate → referee → guardian → hand off.

  1. Call apex_status.
  2. Call apex_find_opportunities across the requested Binance universe.
  3. Call apex_news_sentiment when headlines could change the thesis.
  4. Call apex_review_trade and show Bull, Bear, Constitution Referee, and Guardian separately.
  5. Use Binance Skills or Binance MCP for current account data.
  6. Ask for explicit user confirmation, then re-check the exact order before any Binance write.

A Referee APPROVE means the proposal passed APEX portfolio rules. It does not grant Binance permission. Guardian BLOCK stops the handoff.

04 / SAFETY

Keep credentials and execution at Binance.

  • Never paste a Binance API key into APEX or a public website.
  • Never treat a ranking, funding rate, or headline as a guaranteed return.
  • Never submit an order from an APEX-only result.
  • Keep human confirmation enabled for Binance writes unless you have separately configured a bounded, authorized automation policy.
The one-line mental model:
APEX Skill orchestrates the decision. APEX MCP supplies evidence. Binance Skill/MCP supplies the account and executes only with the user's authorization.
